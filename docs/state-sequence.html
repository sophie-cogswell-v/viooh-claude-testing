The 17-state sequence, as built

Every screen in viooh-claude-testing is pasted verbatim from a Figma frame via get_design_context — no reinterpretation. This page reads that source of truth (src/frames/registry.ts + each frame's Figma node id) and lays out the full walk order, what's actually built for NG vs PG and Overview vs Map, and where the build still diverges from the status table product signed off.

Figma has moved on — the status control is redesigned

Checked the source file again for this page (same link, still node 13141:107499) and the status control itself has changed since the frames below were imported. Worth a look before building anything further against the old pattern.

Old: click the status chip to open a dropdown

What's built today (pending-dropdown, live-dropdown steps) — the chip is closed by default; clicking it reveals a menu of actions.

New: chip + action buttons, always visible, no click-to-reveal

New → chip + Send for approval / Confirm sitting right next to it (greyed out until the line is ready). Pending → chip + Reject / Confirm. Rejected → chip only, no buttons — matches "dropdown disabled" from the signed-off table. Live → chip + Update + a bin icon in place of a labelled Terminate button.

Two things worth a straight answer from design before we build it

1) On Live, Terminate is now an unlabelled trash-can icon rather than text — worth confirming that's deliberate (an icon-only destructive action with no visible label is easy to mis-click or miss entirely) rather than a placeholder.

2) There's also a new, bigger "status id" card at the campaign level (Campaign name/ID/Created by/Status + the same Send for approval/Confirm buttons) that didn't exist before — worth confirming this is meant to sit above the per-line status, not replace it.

Nothing below has been rebuilt against this yet — the walk order, coverage and node table still describe the dropdown-based frames currently in src/frames/. Flagging it here so it's not mistaken for current.

The actual status graph

This is the branching machine product signed off — not a straight line. New and Pending approval are the only statuses that let a person choose between two outcomes; Approved→Live and Live→Ended happen on their own, off the line's schedule, never from a click.

New — Send for approval → Pending approval — Confirm → Approved — start date → Live — end date → Ended
New — Pending approval — Reject → Rejected — Send for approval → back to Pending
New — Pending approval — Approved — Cancel → Cancelled
New — Pending approval — Approved — Live — Terminate → Terminated

Gaps worth knowing about

Found by reading registry.ts against the state list above — none of these block the current demo, but worth a look before the next build pass.

NG never shows a distinct "Approved" screen

The walkthrough jumps from the Pending dropdown straight to Live for NG. Approved is a real status a deal line sits in (sometimes for days, waiting on its start date) — worth its own frame.

NG has no "Ended" screen — falls back to "Rejected"

Different terminal states, different meaning and copy. Right now stepping to Ended on NG just re-shows the Rejected frame, which would read as a bug in a demo.

PG is 5 of 17 states; PG Map is 1 of 17

Built: campaign-empty, schedule-step, location-step, approved, ended. Missing all of: campaign-expanded, deal-created, environment, DSP, CPM, validating, pending, pending-dropdown, live, live-dropdown, rejected — and every Map state past the empty campaign.

PG's "location-step" frame is sourced from a component named PgMapLiveDelivery

Worth a quick visual check against Figma node 367:186632 — the file/component name suggests it may actually be a Map/Live-delivery screen reused for the Location step slot, not a fresh Location-step capture.
